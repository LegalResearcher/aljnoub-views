# Aljnoub Views

يسحب منشورات قناة `@aljnoubvoice` ويرسل طلبات مشاهدة لما يصل إلى خمسة روابط مؤهلة في كل تشغيل.
التشغيل كل 25 دقيقة عبر Supabase `pg_cron`، الذي يرسل `workflow_dispatch` إلى GitHub Actions.

## الإعداد
1. أضف بيانات الحسابات الثلاثة من Settings > Secrets and variables > Actions. لكل حساب أضف:
   - `SITE_USERNAME_1` و`SITE_PASSWORD_1`
   - `SITE_USERNAME_2` و`SITE_PASSWORD_2`
   - `SITE_USERNAME_3` و`SITE_PASSWORD_3`
2. في Supabase Vault أضف سر GitHub باسم `github_actions_token`، ويجب أن يملك صلاحية تشغيل Actions للمستودع.
3. تشغيل يدوي: تبويب Actions > Aljnoub Views > Run workflow.

## كيف يعمل
- أول تشغيل: يأخذ أحدث منشور فقط.
- بعدها: كل منشور جديد يدخل الطابور بالترتيب، ويُنفَّذ الأقدم أولاً.
- كل رابط مؤهل يُعاد في التشغيلات التالية حتى خمسة طلبات ناجحة إجمالًا؛ الطلب الفاشل لا يزيد عداد النجاح.
- الروابط المسجلة مكتملة قبل إضافة عداد النجاحات تبقى مكتملة ولا تُعاد معالجتها.
- الرابط الذي يفشل 3 مرات يُتخطى.
- يختار كل تشغيل حسابًا واحدًا للمهمة كاملة بالتناوب: 1 ثم 2 ثم 3 ثم يعود إلى 1. التناوب مشترك بين التشغيل الرئيسي وإعادة المحاولة اليدوية، ويُحفظ مؤشر الحساب التالي في `state/account_rotation.json` حتى يستمر عبر التشغيلات.
- يجب ضبط أسرار اسم المستخدم وكلمة المرور للحسابات الثلاثة؛ إذا غاب أي سر أو تلف مؤشر الدوران، يتوقف السكربت بأمان بدل تخطي الحسابات أو إعادة استخدام حساب غير مقصود. ملف المؤشر لا يحتوي على بيانات اعتماد.
- يتم تسجيل الدخول إلى الموقع وإرسال الطلب من خلال نموذج المتصفح، مع النقر البرمجي على زر التأكيد لتجاوز العناصر العائمة.

## تصفير الحالة
احذف الملفات داخل مجلد `state/` (ما عدا `.gitkeep`) لبدء من الصفر.

## ملاحظة
المفتاح لا يُكتب في أي ملف. المستودع عام، فملفات `state/` مرئية للجميع.
